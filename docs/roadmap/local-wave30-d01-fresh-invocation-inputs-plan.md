## Concurrency, authority and host-function limits

* The host supplies synchronous trusted `load`/`store` with `undefined` for absence. Its documented behavior must remain correct; a Promise-returning, getter/proxy-bearing, lossy, malicious or unreliable host/input is outside this adapter's proof. Source-bound public release DATA comes from root, not arbitrary active objects.
* There is no compare-and-create/CAS/enumeration interface. Seven reads followed by the release write do **not** atomically reserve a namespace against another writer. Root must allocate a unique nonce and serialize ownership of that namespace with no competing writers from preflight through final readback. If this cannot be guaranteed, stop and request the smallest host atomic-claim interface before implementation; do not pretend a null sentinel or guessed freshness proves it.
* Distinct nonces separate store state; they do not authorize parallel fixture runs on shared ports/Driver/labs or create new permission. Original single-controller, owned PID/Driver binding, private output absence and root runtime reservation still apply. No namespace is reused or repaired after a failure.
* The router is not a sandbox/vault/authentication boundary. It cannot prevent an untrusted host from retaining values or an arbitrary caller from deriving a public physical key. Complete frozen source plus trusted exclusive host/capabilities is required. It creates no additional secret copy, but cannot change the original store backend's custody/serialization.
* Readback needs root to retain the public nonce securely enough to identify this invocation. A lost nonce cannot be repaired by searching old globals, scanning namespaces or copying historical records. Host exceptions propagate; no raw exception is printed by this wrapper and no fallback/retry is implemented. Failure after a real resource starts must still be handled by the unchanged original controller/cleanup contract; memory verification cannot prove installed host reliability or real cleanup.
