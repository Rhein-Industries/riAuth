## Source contract review

**Input, nonce and release.** `d01InvokeFresh` requires the exact seven outer own
fields and original valid 14-field public release, object tools and function
load/store/text/exit before opening the scope. The nonce has an exact lowercase
32-hex string gate and is validated before any host access. Invalid public
release/shape/function/nonce inputs take fixed refusal paths. Unknown/nonstring
canonical keys, physical-name strings and `__proto__` fail the closed seven-key
membership test before the host load/store call. This is a trusted root DATA
contract: getter/proxy/inherited active behavior or malicious host functions are
outside its stated model. No private password/PID/seed/observer field is added.

The original public validator is not an authentication token. Matching runtime/
single-controller/Driver-preflight booleans, session/basename shapes and four
literal pins still needs root's actual reservation and provenance. Likewise the
ASCII length guard is not a cryptographic verifier: root must verify complete
immutable wrapper identity before any use. No source string is an invocation
argument, and no namespace grants tools, runtime permission or fixture ownership.

**All-seven freshness before write.** Under the specified synchronous host,
`d01OpenFreshScope` reads each of the seven physical keys once, accumulating
occupation through the full loop, then refuses if any is not strictly
`undefined`. A scoped `null` is occupied. Returned collision values are compared
only with `undefined`; their properties are not read, copied, printed or retained.
No write occurs on such a collision. If a host read throws, it propagates before
the release write; the wrapper does not reset state or retry a nonce. Only after
all seven normal reads pass does `scope.store` write the supplied public release.
Other six keys remain absent until the original body legitimately writes them.

The scope never loads the old canonical names from the host, scans the store,
copies global records, stores a null seed, migrates history or deletes anything.
That deliberate separation fixes the new invocation's input namespace without
changing the old failed invocation or its undisclosed state.

**Same references and host semantics.** There is exactly one constructor site,
with parameters `tools`, `load`, `store`, `text`, `exit` and the frozen source
identifier. Its one call is exactly
`invocation(input.tools,scope.load,scope.store,input.text,input.exit)`, awaited and
returned. Scoped functions close over one nonce and the original host functions;

## Authority, concurrency and memory prerequisites

Seven reads followed by one write offer no CAS or compare-and-create. Another
writer could occupy a key between them; the source explicitly makes trusted
exclusive nonce ownership from preflight through final readback a prerequisite.
The adapter does not detect/repair that race, and fake-store memory behavior could
not certify real concurrent safety. If root cannot guarantee this ownership, the
stated design is inapplicable until a separately owned atomic host interface is
reviewed. No automatic new nonce, claim sentinel or host API is proposed here.

Distinct nonce stores do not permit parallel controllers on shared ports/Driver/
labs. The fixed workspace and runtime owner's original authority, source, current
Driver binding, private paths, actual resource inputs and single-controller gates
remain. Losing the nonce has no global-search/fallback repair. Host failure,
lossiness/Promise return, proxies or hostile records remain excluded assumptions,
not demonstrated supported behavior. Routing adds no hard host-I/O quota or kernel
deadline; original 840/900/180/600/5-second and nonrenewed 60-second contracts are
unchanged, with whole60 still expressly unproved.

The nine future memory-table groups are meaningful proposals: old-global
noninterference, each occupied/null key, closed input/keys, direct references,
same-nonce refusal and the non-atomic limitation, synthetic secret separation,
durable observation/false-state preservation, whole-source/call-boundary binding
and finite privacy failure. They are not observed cases/counts or executed proof.
Its proposed <=30s child/<=35s owner, private finite packet/caps/join/absence and
